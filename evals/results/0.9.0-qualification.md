# Software Factory 0.9.0 qualification

Date: 2026-10-27

## Candidate and harness

- Baseline: `origin/main` at `9a067e507c4e7703ca637177696083ff4e36cf23` (`0.8.1`).
- Candidate: uncommitted `codex/factory-single-loop` working tree (`0.9.0`).
- Runner: fresh, ephemeral Codex sessions using project-local candidate or baseline skills, `gpt-6.1-sol`, medium reasoning, and a read-only sandbox.
- Each runner received only the case prompt and fixture. It did not receive the expected behaviors, failure signals or scorecard.
- A separate fresh session judged the saved outputs against the published rubric.
- No external action, consumer repository edit or product test suite was run.

The preferred Claude Code route was unavailable because the local OAuth session had expired and could not be refreshed. Qualification continued through the host-neutral Codex route supported by the Factory contract.

## Generic suite

The baseline failed all seven cases. The candidate passed all seven without an explicit hard-gate violation.

| 07 moving target | 25/34, fail | 31/34, pass | 34/34, pass after refinement |

Initial aggregate results were 156/238 for the baseline and 222/238 for the candidate. The focused rerun after refinement confirmed that cases 05, 06 and 07 each reached 34/34. Cases 01 through 04 were unchanged and were not rerun.

The focused rerun confirmed that the candidate:

- preserves stable finding and evidence IDs during bounded fixes;
- reuses evidence only when its candidate, inputs, environment and limits still apply;
- reruns affected checks and any unavoidable consumer-required matrix;
- assigns the complete suite to one local or remote owner;
- reads concise remote conclusions before opening failure artifacts;
- explains that advancing branch histories cause target drift, while worktrees only isolate files;
- requires combined-revision evidence when parallel changes may interact.

## Release assessment

The candidate qualifies under this suite. It improves every generic case, passes the two frozen trace checks and preserves consumer neutrality.

These results validate the Factory's written orchestration decisions. They do not prove that a consumer's application code, CI workflow or persona journeys pass. Each real task must still bind verification evidence to its exact candidate or proven integration revision.
